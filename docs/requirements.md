# SPARKPLUS LMS 요구사항 명세 v1

## 1. 목적과 범위

SPARKPLUS 임직원 최대 150명이 사용하는 사내 교육용 LMS를 구축한다. 기존 React 프로토타입의 화면을 유지하면서 데모 로그인, 하드코딩 데이터, `localStorage` 기반 저장을 실제 인증, PostgreSQL 데이터베이스, 백엔드 API로 교체한다.

1차 범위는 관리자, 학습자, 조직 리더가 사용하는 단일 회사용 LMS다. 기존 교육 이력의 마이그레이션은 하지 않는다.

## 2. 사용자와 인증

- Google Workspace 계정으로 로그인한다.
- 이메일 도메인이 `@sparkplus.co`인 계정만 허용한다.
- Google 인증 성공 후에도 LMS `users` 테이블에 등록된 활성 사용자만 접속할 수 있다.
- 기본 역할은 `ADMIN`, `LEARNER` 두 가지다.
- 조직 리더는 별도 역할이 아니라 학습자에게 조직 조회 권한을 추가하는 방식으로 지정한다.
- 비활성 또는 삭제 처리된 사용자는 로그인할 수 없다.
- 최초 관리자는 배포 시 환경변수 또는 초기 시드로 등록한다.

## 3. 조직과 사용자 관리

- 조직은 `개발본부 > 부동산팀 > 개발파트`처럼 부모-자식 계층으로 관리한다.
- 조직 깊이는 3단계로 제한하지 않는다.
- 사용자는 하나의 주 소속 조직을 가진다.
- 직책은 미리 고정하지 않고 문자열로 입력하며, 과정 배정 화면에서는 현재 사용자 데이터에 존재하는 직책을 선택지로 제공한다.
- 한 명을 여러 조직의 리더로 지정할 수 있고 한 조직에도 여러 리더를 지정할 수 있다.
- 조직 리더는 담당 조직과 모든 하위 조직 구성원의 학습 현황을 조회한다.
- 사용자는 화면에서 한 명씩 등록하거나 `.xlsx` 파일로 일괄 등록할 수 있다.
- 엑셀 가져오기는 사번, 이름, 회사 이메일, 조직 경로, 직책, 조직 리더 여부를 검증하고 행별 성공·실패 사유를 제공한다.

### 3.1 사용자 상태

- `ACTIVE`: 로그인 및 학습 가능
- `INACTIVE`: 로그인 및 신규 배정 불가, 기존 기록 보존, 재활성화 가능
- `DELETED`: 일반 목록에서 숨김, 로그인 불가, 학습·수료·감사 이력 보존
- 학습 이력이 전혀 없는 사용자는 관리자가 명시적으로 확인한 경우에만 영구 삭제할 수 있다.

## 4. 과정과 배정

### 4.1 과정 공개 유형

- `PUBLIC`: 모든 활성 사용자가 과정 카탈로그에서 찾아 직접 신청할 수 있다.
- `ASSIGNED_ONLY`: 배정 대상자에게만 표시한다.

### 4.2 배정 대상

관리자는 과정 등록 또는 수정 시 다음 대상 중 하나 이상을 선택할 수 있다.

- 전체 활성 사용자
- 특정 조직 및 그 하위 조직
- 특정 직책
- 특정 개인

여러 조건은 기본적으로 OR로 결합한다. 여러 조건에 중복으로 포함된 사용자에게도 수강 등록은 한 건만 생성한다. 조건 배정 후 새로 입사하거나 조직·직책이 변경된 사용자의 자동 반영 여부는 배정별 `dynamic_assignment` 설정으로 관리하며 기본값은 활성화다.

### 4.3 필수 및 선택 과정

- 필수과정은 사용자가 수강을 취소할 수 없다.
- 공개 선택과정과 배정된 선택과정은 수료 전까지 취소할 수 있다.
- 수료한 과정은 사용자가 취소할 수 없다.
- 취소 시 진도는 보존하며 재신청 시 이어서 학습한다.
- 관리자는 배정 회수와 진도 초기화를 별도 작업으로 수행할 수 있다.
- 필수과정에는 마감일을 설정할 수 있다.

## 5. 차시와 영상

### 5.1 YouTube 영상

- 회사 YouTube 계정에 업로드된 영상을 LMS에 임베드한다.
- 원본 영상은 Google Drive에 별도로 보관할 수 있다.
- DB에는 YouTube 영상 ID와 선택적인 Drive 원본 파일 ID를 저장한다.
- YouTube 플레이어에서 재생 상태와 현재 위치를 주기적으로 수집한다.
- 서로 다른 시청 구간을 병합해 전체 영상의 60% 이상을 실제로 재생했을 때 `학습 완료하고 다음 차시` 버튼을 활성화한다.
- 단순 탐색으로 건너뛴 구간과 이미 본 구간의 반복 재생은 추가 진도로 중복 인정하지 않는다.
- 학습자가 완료 버튼을 눌러야 차시가 최종 완료된다.
- 배속과 탐색은 허용한다.
- 네트워크 단절 시 마지막으로 서버에 확인된 진도를 기준으로 복구한다.

시청 구간 측정은 사내 학습 확인을 위한 합리적 수준으로 구현하며, YouTube 임베드의 특성상 시험 감독 수준의 부정 방지를 보장하지 않는다.

### 5.2 기타 차시

문서, 링크, 오프라인 교육 등 영상 이외 유형을 확장할 수 있도록 차시에 `content_type`을 둔다. 1차 개발에서는 YouTube 영상과 첨부자료를 우선 지원한다.

## 6. 퀴즈, 설문, 수료

- 퀴즈는 차시 또는 과정에 연결할 수 있다.
- 학습자가 답안을 제출하면 즉시 정답, 오답, 해설을 보여준다.
- 점수와 모든 응시 이력을 저장한다.
- 합격 점수와 응시 횟수 제한은 두지 않는다.
- 과정에 퀴즈가 있으면 최소 한 번 답안을 제출해야 수료할 수 있다.
- 과정에 필수 설문이 있으면 설문 완료 기록이 있어야 수료할 수 있다.
- 모든 필수 차시 완료, 퀴즈 제출, 필수 설문 완료 조건을 모두 만족하면 서버가 수료 처리한다.
- 프론트엔드는 수료 상태를 직접 변경할 수 없다.

## 7. 파일과 Google Workspace 연동

### 7.1 Google Drive

다음 파일을 Drive에 저장한다.

- 영상 원본
- 과정 교재 및 첨부파일
- 공지 첨부파일
- 발급된 수료증 PDF
- 보고서 내보내기 파일

DB에는 Drive 파일 ID, 파일명, MIME 타입, 크기, 폴더 ID, 업로더, 업로드 시각만 저장한다. 파일 접근 전 백엔드에서 사용자의 권한과 수강 관계를 확인한다.

### 7.2 Google Sheets

- 수강 현황
- 미수료자 명단
- 수료 내역
- 조직별 교육 통계
- 동기화 오류

1차 버전에서는 관리자가 내보내기 버튼을 눌러 Sheets를 생성 또는 갱신한다. Sheets를 운영 데이터의 원본 DB로 사용하지 않는다.

## 8. 수료증

- 수료 확정 시 고유 수료증 번호를 발급한다.
- 백엔드가 사용자, 과정, 수료일을 포함한 PDF를 생성한다.
- PDF를 Google Drive에 저장하고 DB에는 Drive 파일 ID와 발급 이력을 남긴다.
- 학습자는 본인의 수료증만 조회하고 내려받을 수 있다.
- 관리자는 모든 수료증을 조회하고 재발급할 수 있다.

## 9. 비기능 요구사항

- 전체 사용자와 최대 동시 접속자는 각각 150명을 기준으로 한다.
- 모든 관리자 변경 작업과 민감한 상태 변경은 감사 로그를 남긴다.
- 서버 비밀키, OAuth 비밀값, 서비스 계정 키를 소스 저장소에 커밋하지 않는다.
- API는 서버에서 인증과 권한을 매번 확인한다.
- 데이터베이스 변경은 마이그레이션으로 관리한다.
- 날짜는 DB에 UTC로 저장하고 화면에서 Asia/Seoul 시간대로 표시한다.
- 주요 기능에 자동 테스트를 작성한다.

## 10. 1차 범위에서 제외

- 기존 교육 이력 마이그레이션
- 결제 기능
- 외부 고객용 멀티테넌트
- 실시간 화상 강의
- 시험 감독 수준의 영상 시청 및 부정행위 방지
- YouTube 영상의 LMS 내부 업로드 자동화
