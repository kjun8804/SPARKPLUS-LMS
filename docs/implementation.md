# 구현 계획

## 1. 개발 원칙

- 기존 UI를 유지하고 화면별 하드코딩 데이터를 API로 순차 교체한다.
- 인증과 권한은 가장 먼저 구현한다.
- 프론트엔드가 아닌 서버가 배정, 진도, 수료를 최종 판정한다.
- 한 단계마다 자동 테스트와 수동 검증을 완료한 뒤 다음 단계로 넘어간다.
- 기존 `localStorage` 키는 대응 API가 안정화된 이후에만 제거한다.

## 2. 권장 프로젝트 구조

```text
SPARKPLUS-LMS/
├─ src/                     React 프론트엔드
│  ├─ api/
│  ├─ components/
│  ├─ features/
│  ├─ pages/
│  └─ auth/
├─ server/                  Node.js + TypeScript 백엔드
│  ├─ src/
│  │  ├─ auth/
│  │  ├─ users/
│  │  ├─ organizations/
│  │  ├─ courses/
│  │  ├─ enrollments/
│  │  ├─ progress/
│  │  ├─ quizzes/
│  │  ├─ certificates/
│  │  ├─ google/
│  │  └─ common/
│  ├─ migrations/
│  └─ tests/
└─ docs/
```

백엔드 프레임워크와 ORM은 구현 시작 전에 확정한다. 기본 제안은 Node.js/TypeScript, PostgreSQL, 타입 안전한 마이그레이션 도구다.

## 3. 단계별 구현

### Phase 0. 설계 기준선

- 요구사항, DB, API, 권한 문서 검토
- 미결정 항목 기록
- 개발·검수·운영 환경 구분
- 브랜치 전략과 환경변수 예시 작성

완료 조건: 개발자가 문서만 보고 1차 테이블과 API를 구현할 수 있다.

### Phase 1. 백엔드와 DB 기반

- TypeScript 백엔드 생성
- PostgreSQL 연결
- 마이그레이션과 시드 체계 구축
- 공통 오류 응답, 로깅, 입력 검증
- 상태 확인 API와 테스트 환경 구축
- `organizations`, `users`, `organization_leaders`, `audit_logs` 생성

완료 조건: 빈 DB에서 마이그레이션과 초기 관리자 시드를 재현할 수 있다.

### Phase 2. Google 인증과 권한

- Google OAuth 로그인
- `@sparkplus.co` 도메인 제한
- 등록·활성 사용자 확인
- 세션과 로그아웃
- ADMIN/LEARNER 미들웨어
- 조직 리더 범위 판정
- 마지막 관리자 보호

완료 조건: 관리자, 일반 학습자, 조직 리더, 미등록·비활성 사용자의 접근 결과가 자동 테스트로 검증된다.

### Phase 3. 조직과 사용자 관리

- 조직 트리 CRUD와 순환 참조 방지
- 사용자 CRUD, 비활성화, 삭제 처리
- 조직 리더 지정
- `.xlsx` 미리보기·검증·반영
- 기존 관리자 화면을 실제 API에 연결

완료 조건: 관리자 화면에서 만든 조직과 사용자가 DB에 저장되고 Google 로그인과 연결된다.

### Phase 4. 과정과 차시

- 과정·차시·첨부파일 테이블과 API
- 공개/배정전용 및 초안/운영 상태
- YouTube ID 검증과 차시 순서 관리
- Google Drive 파일 등록 기반
- 과정 카탈로그와 관리자 편집 화면 연결

완료 조건: 관리자가 등록한 과정이 권한에 맞게 학습자 화면에 표시된다.

### Phase 5. 배정과 수강

- 전체·조직·직책·개인 규칙
- 중복 제거와 대상 미리보기
- 동적 배정 재계산 작업
- 공개과정 신청
- 선택과정 취소, 필수과정 취소 차단
- 관리자 배정 회수와 진도 초기화

완료 조건: 조건별 대상자와 실제 수강 건이 일치하고 조직·직책 변경 시 정책대로 반영된다.

### Phase 6. YouTube 학습 진도

- YouTube IFrame 플레이어 연동
- heartbeat와 시청 구간 병합
- 60% 완료 버튼 활성화
- 이어보기와 네트워크 복구
- 과정 진도 재계산
- 비정상 점프와 변조 방어

완료 조건: 탐색으로 건너뛴 구간은 인정되지 않고 실제 고유 시청 구간 60% 이후에만 완료된다.

### Phase 7. 퀴즈, 설문, 수료

- 관리자 퀴즈 편집
- 정답 제외 조회와 서버 채점
- 무제한 응시 이력
- 설문 완료 기록
- 차시+퀴즈+설문 수료 판정
- 완료 이벤트의 중복 처리 안전성

완료 조건: 조건 일부가 빠지면 수료되지 않고 모든 조건 충족 시 한 번만 수료 처리된다.

### Phase 8. 수료증, Drive, Sheets

- Drive 폴더와 파일 정책
- 수료증 PDF 생성·Drive 저장·재발급
- 파일 권한 확인 다운로드
- 수강·미수료·수료 현황 Sheets 내보내기
- 실패 재시도와 운영 로그

완료 조건: 수료증과 보고서가 Drive에 생성되고 허가된 사용자만 접근한다.

### Phase 9. 공지, 대시보드, 프론트엔드 정리

- 공지 CRUD와 대상 설정
- 관리자 통계
- 조직 리더 대시보드
- `App.jsx` 기능별 분리
- API 클라이언트와 로딩·오류 상태 통일
- 대체가 끝난 업무용 `localStorage` 제거

완료 조건: 프로토타입 하드코딩 업무 데이터가 실제 DB 데이터로 완전히 교체된다.

### Phase 10. 보안, 성능, 배포

- 최대 150 동시 사용자 부하 검증
- OAuth, 세션, CORS/CSRF, 입력 검증 점검
- 백업과 복구 연습
- 개인정보 보존·삭제 정책 적용
- 운영 모니터링과 오류 알림
- 관리자 운영 매뉴얼 작성

완료 조건: 검수 환경의 핵심 사용자 흐름이 통과하고 배포·복구 절차가 문서화된다.

## 4. 첫 번째 구현 묶음

첫 개발 PR 또는 마일스톤은 다음 범위로 제한한다.

1. 백엔드 프로젝트와 PostgreSQL 연결
2. 공통 환경변수와 오류 처리
3. 조직·사용자·조직 리더 마이그레이션
4. 최초 관리자 시드
5. Google 로그인 골격과 `@sparkplus.co` 검증
6. `/auth/me`와 기본 권한 테스트

UI 연결, Drive, Sheets, YouTube 진도는 이 기반이 검증된 후 진행한다.

## 5. 개발 전에 준비할 외부 항목

- 최초 관리자 이메일
- Google Cloud 프로젝트와 승인된 OAuth 리디렉션 주소
- OAuth 클라이언트 정보(환경변수로만 저장)
- Drive 보관 폴더 또는 Shared Drive
- Sheets 보고서 대상 폴더
- 운영 PostgreSQL과 개발용 PostgreSQL
- 실제 조직 초기 목록 또는 최소 테스트 조직

서비스 계정 JSON이나 OAuth 비밀값은 저장소와 이슈, 채팅에 첨부하지 않는다.

## 6. 검수 핵심 시나리오

1. 등록된 활성 `@sparkplus.co` 사용자만 로그인한다.
2. 조직 리더가 자기 조직과 하위 조직만 조회한다.
3. 과정 배정 규칙이 중복 없이 대상을 생성한다.
4. 필수과정은 취소되지 않고 선택과정은 취소·재신청된다.
5. YouTube 시청 구간 60% 전에는 차시를 완료할 수 없다.
6. 모든 차시, 퀴즈 제출, 필수 설문 완료 후에만 수료된다.
7. 수료증과 보고서가 Drive/Sheets에 생성되고 권한이 검증된다.
8. 사용자 삭제 후에도 기존 교육 이력과 감사 로그가 유지된다.
