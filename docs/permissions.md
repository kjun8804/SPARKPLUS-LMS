# 권한 정책

## 1. 권한 모델

기본 역할은 `ADMIN`, `LEARNER` 두 가지로 유지한다. 조직 리더는 역할을 추가하지 않고 `organization_leaders` 관계로 권한 범위를 부여한다.

권한 판정은 프론트엔드 표시 여부와 관계없이 모든 API에서 서버가 수행한다.

## 3. 조직 범위 판정

조직 리더의 조회 가능 사용자 집합은 다음과 같다.

1. `organization_leaders`에서 현재 사용자가 담당하는 활성 조직을 찾는다.
2. 각 담당 조직의 모든 활성 하위 조직 ID를 찾는다.
3. 해당 조직들에 소속된 사용자의 학습 요약만 반환한다.
4. 다른 조직 ID를 API 매개변수로 전달해도 서버에서 거부한다.

리더에게 기본적으로 노출하는 정보는 이름, 사번, 조직, 직책, 배정 과정, 진도율, 수료 상태, 마감일, 마지막 학습일, 퀴즈 응시 여부다. 이메일과 세부 퀴즈 답안은 1차 버전에서 노출하지 않는다.

## 4. 사용자 삭제 정책

- `INACTIVE`는 가역적이며 로그인과 신규 배정만 차단한다.
- `DELETED`는 일반 조회에서 숨기며 로그인과 재활성화를 차단한다.
- 학습 이력이 있는 사용자의 `users` 행과 이력은 물리적으로 삭제하지 않는다.
- 학습 이력이 없는 사용자의 영구 삭제는 관리자 재확인과 감사 로그를 필요로 한다.
- 삭제된 사용자의 Google 식별자와 이메일 재사용 정책은 보안 검토 후 확정한다. 기본값은 재사용 시 새 사용자로 등록하되 과거 기록과 자동 병합하지 않는 것이다.

## 5. 파일 접근 정책

- 사용자는 공개과정 또는 본인에게 배정·신청된 과정의 파일만 접근한다.
- 조직 리더 권한만으로 다른 학습자의 과정 파일을 내려받을 수 없다.
- Drive 파일은 가능한 경우 외부 공개 링크 대신 백엔드가 권한을 확인한 뒤 제공한다.
- 관리자 파일 업로드, 삭제, 교체는 감사 로그 대상이다.

## 6. 관리자 보호 정책

- 마지막 활성 관리자는 비활성화하거나 삭제할 수 없다.
- 관리자가 자신의 관리자 권한을 직접 제거할 수 없게 한다.
- 권한 변경, 사용자 삭제, 진도 초기화, 배정 회수, 수료 취소 및 수료증 재발급은 감사 로그를 남긴다.
- 중요한 작업은 대상, 영향, 복구 가능 여부를 확인하는 확인창을 거친다.
